# Thumbnail direction

Use this when generating the finished image suite. The source guides are the user-provided `2.2 - 10 Rules of Thumbnails.pdf` (5 pages) and `2.2 16 Engaging Thumbnail Frameworks.pdf` (9 pages). These are practitioner design guidance, not measurements of CTR. Do not redistribute their pages in the plugin. Their file locations are user-specific and are not required for the portable workflow below.

## Apply the ten rules as design review

1. Make the visual promise match the actual episode and first frame.
2. Extend the title's information gap; retain an unanswered question.
3. Show tension that fits the story without exposing the full outcome.
4. Let the image add information instead of repeating the complete title.
5. Keep roughly three core elements or fewer. A crowd, city or repeated group can read as one mass when composed clearly.
6. Review at small feed scale and with a squint; the premise must remain readable.
7. Use subject/background separation and contrast deliberately.
8. Preserve recognizable creator and visual identity across the suite.
9. Choose faces/emotion that belong to the episode, rather than automatic exaggerated reactions.
10. Keep one clear dominant subject even if other elements create context.

These are review heuristics. The guide's framework list is a choice set, not a requirement to use all sixteen in every project. Its suggestion to brainstorm five options does not require generating 500 images for a 100-episode brief. Agree the selected image count/variant scope; ensure every requested episode gets a finished image.

## Framework menu

| Framework | Use when | Watch for |
| --- | --- | --- |
| Before/after | Transformation carries the story | A truthful, meaningful contrast |
| Social UI | An actual message/review/question is evidence | Invented endorsements or unreadable UI |
| Three-step progression | Middle stage adds a compelling turn | Too many small panels |
| Compelling screenshot | A captured moment carries authenticity | A frame that does not explain the promise |
| Posed portrait | Creator trust/personality is the subject | Weak fit for action spectacle |
| Posed action | One action expresses the premise | Action absent from the episode |
| Specific day | Elapsed challenge/progression matters | A fictitious duration or spoiled ending |
| Graphic | A simple visual makes a comparison legible | Complex charts at feed scale |
| Landscape | Environment is itself extraordinary and consequential | Scenery without a subject |
| Map/aerial | Route, territory or geography creates stakes | A diagram requiring game knowledge |
| Product/object | One object carries curiosity | Mere product placement |
| Text continuation | A small cue adds missing context | Repeating the full title |
| Repetition | Quantity creates the spectacle | Tiny indistinguishable clutter |
| Size difference | Scale comparison is the story | Perspective exaggeration that misstates the premise |
| News frame | Actual coverage belongs to the story | False implication that an outlet covered it |
| Amplified reality | Emphasizing a real story element speeds understanding | Fabricating a spectacle production cannot deliver |

Combine frameworks only when the focal hierarchy still works. Match choice to viewer promise and source examples.

## Source-following and brand-directed briefs

Inspect the actual reference pixels before writing a source-following prompt. Preserve the requested camera angle, subject positions/proportions, focal scale, foreground/background balance, contrast blocks and text placement. Replace the creator and relevant content; specify the intentional small change. Retain the real source-video link and image. A generic description of the source channel's style is not a 1:1 composition brief.

For a spectacle/cinematic direction, identify the visual premise: giant scale, overwhelming opposition, dangerous-looking but in-game challenge, impossible environment, extreme contrast or an earned transformation. Keep the focal situation immediately understandable. Detail and production polish should support this hierarchy, not fill every corner. The webpage can stay simple while images feel grand.

For Stokes Twins, the requested feeling is MrBeast/MrBeast Gaming-level spectacle and cinematic finish while remaining Stokes-identifiable. This is the user's taste direction, not proof of performance. Source actual relevant thumbnails, define how the twins/cast appear, use consistent approved identity references, and ensure the episode can produce what the image promises. Neither GTA's logo nor game knowledge should be necessary to understand the core visual problem.

## Prompt and generation record

Each selected image needs: idea/format ID, final title, viewer question, main subject, identity references, reference video/thumbnail, layout and scale, setting/action, lighting/contrast, emotion, framework, text if needed, intentional adaptation, truthful scope, aspect ratio, exact final prompt and output selection.

Check current tools and model identity before generation. Preserve requested models; obtain a user-approved alternative only if needed. If the tool has no verifiable model selector, record `actual_model: unverified`; do not attribute outputs to a named model. Prior Nizar permission to use an unverified route is not a universal instruction for all future clients.

Generate native 16:9 where supported. Export consistent 1280x720 or another agreed 16:9 size, with originals retained when meaningful. Use responsive previews where helpful. Record hashes, prompt files, reference IDs, generator/tool, actual/requested model and variant selection. Do not declare an image delivered from a job submission alone.

## Review the suite

Inspect each image and a contact sheet for identity, anatomical/face issues, game/action coherence, text accuracy, frame boundaries, repeated pose fatigue and visual consistency. Review at about 320x180 and 160x90. Verify the promise remains legible without the title and that title plus image adds a question. Check the twins' distinguishability where important and do not accidentally substitute a generic person.

Check every idea-to-image mapping by ID and checksum. All images must appear in the unified gallery, the shared viewer and the bulk package. Prompts-only slots remain incomplete. Record CTR or thumbnail-test results after real publication when available; creative review alone cannot certify CTR.

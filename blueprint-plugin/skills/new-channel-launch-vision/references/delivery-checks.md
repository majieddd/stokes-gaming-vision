# Delivery checks

## Editorial and research

- Intake answers and attachments are reflected accurately; unresolved critical inputs and tentative assumptions remain visible.
- Portfolio was checked with the user before full expansion. Counts match the project scope and each format has a distinct engine.
- Every episode has an understandable promise, specific intro beats, an earned payoff, production needs and a finished thumbnail.
- Shape and ingredient evidence are separated. Source IDs/links/thumbnails are real; relevance and metric basis are retained. Counterexamples and gaps remain visible.
- New-channel targets and budget scenarios are not presented as measured forecasts. Schedule slot counts, deadlines, lead times and cost arithmetic reconcile or carry explicit pending decisions.
- Claims preserve standing, measured state, application mode, limits and prohibitions. Private analytics are used only within authorized scope.
- Post-production charts are actual curves with source/date and timestamps. Qualitative observations do not masquerade as quantitative retention.

## Structured package

Run `validate_launch_plan.py` in draft and complete modes. Complete mode verifies requested counts, IDs and mappings, per-format episodes, summaries/openings, source records, local selected images and prompts, hashes and additive budgets. Evidence coverage gaps are warnings unless the scope requires full coverage; a warning is not converted into an invented source.

Deliver source data, plan/intake, selected images, exact prompts, reference registry, image manifest and all-image ZIP. Reopen the ZIP, test CRCs, count files, confirm filenames and manifest hashes. Do not include secrets, private source PDFs, unrelated files or another client's private analytics in a public package.

## Website behavior

One gallery and one shared card renderer. Check total/family counts, search across all additions, evidence filters, pagination, all-ideas mode, empty state, ID deep links and legacy links when present. Verify the modal crosses format boundaries, download targets match IDs, arrows/Escape work and focus returns to the trigger. Check images for broken paths and lazy-load behavior.

Inspect desktop and mobile widths, contrast, overflow, long titles/filter labels, stable 16:9 thumbnails, consistent cards, navigation and readable disclosure content. Check real retention selection/markers only when provided. Capture a screenshot that demonstrates the final user-facing result. Browser review is required for a website; data validation alone does not establish a working UI.

## Release

Respect the delivery audience. A private new-channel brief is not automatically authorized for the public site because earlier work was public. Proceed within existing authorization for this specific deliverable; otherwise finish a concrete reviewable result before any publication question.

When publishing, include the complete asset set and preserve unrelated studies. Check the actual branch/remote, concurrent changes, deployment status and live HTTP/hash parity. An active deployment, commit or delegation is not completion. Open the final live version and verify representative controls and image/source/download paths.

For the existing Influint Pages workflow, study pins/guards can protect a reviewed source revision from automated publisher overwrites. Keep that as a project adapter, not a mandatory hosting design for every site. Never run a thumbnail-only legacy integration script over a richer playbook without inspecting its behavior.

## Final report

Give usable document/site and package links, what is complete, what was actually tested, and any material access/evidence gaps. State image model uncertainty when applicable. Do not call a reviewed format board the full 100-episode deliverable, or a local artifact a published site.
